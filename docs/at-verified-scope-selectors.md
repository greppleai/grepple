# Verified `--at` scope selectors: acceptance contract

Status: local CLI, parser-backed resolver, transport guards, registry-wide rendered-token round-trips and focused integration tests implemented and validated in this checkout. This checkout has not been installed; a different installed CLI may not accept this syntax yet. The inherited incomplete-Go false annotation was addressed by rejecting a bodyless declaration followed on the same line by a parser ERROR sibling; parser and CLI regression tests ensure neither its label nor an exact/shorthand selector succeeds. This document records the acceptance contract and historical design evidence; never treat a displayed annotation suffix as a parseable or authoritative source boundary.

## Invocation and meaning

```sh
grepple --line-only -F 'options.Params.Limit == 0' internal/cli/search/execution.go
# An annotated match may show: @if:83-86 @func:54-132
grepple --at internal/cli/search/execution.go @if:83-86
grepple --at internal/cli/search/execution.go @if:83
```

- `--at PATH @KIND:START-END` asks for **exactly** the current, parser-verified inclusive span with the named public kind. The token shape intentionally matches `--line-only` output. `--at PATH @KIND:LINE` is shorthand: at that one-based source line, choose a single unambiguous verified span of that kind containing the line. Both inputs refer to the *current local file*, not to copied output or its hashes; `PATH` is the entire `--at` operand. A bare `@...` is not a search query, and a selector after a legacy `--at PATH:LINE[-END]` is invalid.
- For explicit bounds, compare the complete `(kind, startLine, endLine)` tuple against the classified current syntax; requiring only containment or accepting a guessed/clamped bound is forbidden. Prefer using the same parser-owned allowlist, error policy and typed nearest/scope projection as `LineScopeAnnotations`, not a separate raw-grammar-kind classifier. A span emitted as a nearest or scope role should be retrievable without a prior match line when unchanged, including an ancestor at whose start line a nested node is closer; targeted traversal may be needed beyond a projection of only two roles at one line. If distinct nodes of the same kind and identical line bounds cannot be distinguished, the requested **line range** is still uniquely determined; never invent a different range.
- For shorthand, deduplicate identical spans, then require **one** candidate of the requested kind at `LINE`; if nested same-kind nearest and scope identify distinct spans, reject as ambiguous and suggest copying an explicit `@KIND:START-END`. Do not silently choose the smallest/largest. When the parser cannot establish the kind and both endpoints confidently (including error subtrees, ambiguous same-line sibling content or unbounded YAML), return no selection. Source text that merely resembles an annotation is not evidence: a hand-typed token can succeed only if the parser independently proves that exact construct now exists.
- Reject invalid/unlisted kind, zero/negative/descending/overflow bounds, out-of-file lines, unsupported/plain or binary content, path escapes, absent verified construct, stale/mismatched explicit bounds and ambiguous shorthand with clear diagnostics. Re-reading/reparsing detects stale **bounds**, not arbitrary same-span edits: without a content digest, unchanged syntax bounds do not prove the bytes match an earlier search result. Re-read clean source before an anchored write. Do not parse suffixes out of the decorated human match line; typed JSON keeps `text`, `nearest` and `scope` separate.
- Keep legacy `--at PATH:LINE[-END]` syntax and its existing EOF partial-range behavior. Verified selectors themselves must never clamp. Existing context flags can explicitly add neighbor lines, but without context the selected lines are exactly the verified span; `--line-only`, default structural and `--json` return ordinary literal `--at` content, not decorated search rows or extra matched lines. A one-line selected construct must still be treated as an **exact** range, not expanded to its enclosing declaration. No implicit callable/related graph expansion follows a scope token. Existing explicit `--related` semantics and graph commands must not change for legacy references.
- Initial support is **local only**. A configured server does not by itself cause remote search; reject a selector before network access if the effective request would be remote (`--remote`, `--remote-only`, `--server`, or a remote cursor), while retaining existing `--local` override behavior. Do not serialize selector text to `Request.At`: the current backend does not validate it. Keep legacy remote `--at PATH:LINE[-END]` behavior untouched. A future remote selector needs its own end-to-end capability contract, not a router-only acknowledgement.
# SearchArgs @struct:25-79

`--outline` prints parser-verified local declaration destinations by default:

```sh
grepple --outline internal/cli/search/args.go
# SearchArgs @struct:25-79
grepple --at internal/cli/search/args.go @struct:25-79
```

An outline selector uses the effective parser language's stable public declaration word, not the outline display kind and not a raw tree-sitter node name: TypeScript/JavaScript `function`, Python `def`, Kotlin `fun`, Rust `fn`, and Go/Swift `func`. For example, a TypeScript row is `formatUser @function:8-12`, while a Go row is `Run @func:2-5`. Rows without a verified scope retain their native legacy `START-END\tKIND\tNAME` form. `--outline --json` remains structured data without selector decoration. Small files do not fall back to raw content in human outline mode. Tokens are local-only and must not be inferred from graph ranges, remote artifacts, or architecture import/call evidence.

For compatibility, the previous normalized `@func` is accepted as local input for a native function scope, but newly verified local presentation emits its native token. It is not an alias for arbitrary scope kinds, and a wrong native kind still fails verification.

## Go API (local only)

Use the exported `api.ScopeSelector` with `api.NewSearchPlan(api.SearchPlanOptions{At: "src/file.go", AtScope: &api.ScopeSelector{Kind: "if", StartLine: 83, EndLine: 86, Exact: true}})` and then `api.SearchAt(plan)`. `At` is the bare local path, not `PATH:LINE` or decorated source; set `Root` when restricting its source universe. For shorthand set `Exact: false` and `StartLine` and `EndLine` to the same hit line. The plan copies the selector; `SearchAt` verifies the current file again, while `SearchRequest`/remote consumers intentionally have no selector field. Legacy `api.SearchAt` without `AtScope` still accepts `At: "src/file.go:83-86"`.
## Ownership and compatibility evidence (design snapshot, 2026-10-14)

- `internal/cli/search/args.go:25-65,80-150,190-240,260-277,334-379` parses two-positionals as `Query`/`Globs` today and rejects either with `--at`; it also computes `remoteEnabled` and disables default scope decoration for `--at`. `internal/cli/search/execution.go:54-132,134-167,285-308` chooses local versus remote, fetches once, then runs anchors/render. `internal/cli/search/remote.go:20-53,87-91` converts `Params` to the wire request; `internal/search/request.go:3-10` copies `Params.At` onto `Request.At`. - `internal/search/at.go:15-143,145-161` owns root confinement, binary/UTF-8 handling, line resolution, exact range versus structural declaration and `AtFromDocument` for caller-owned parsed source. `api/search_service.go:128-134` calls `search.At`; `internal/cli/ask/backend_tools.go:99-146` calls both local `At` and `AtFromDocument` and sends remote legacy references. Selector support/guarding cannot assume the CLI is the only consumer; preserve document-source consistency and reject unsupported remote tool references instead of forwarding them. Existing `internal/search/at_test.go:74-118` asserts range/exact-line compatibility.
- `internal/parser/scope_annotations.go:5-96,103-172` collects nearest and navigable scope by classified AST nodes per requested hit, currently choosing up to two candidates; `scope_annotations_content.go:5-35` routes Markdown/JSON/YAML versus code/text. `scope_annotations_markdown.go` uses parser-backed headings; `scope_annotations_structured.go` drops uncertain/ambiguous content. - Focused `grepple graph callers --at internal/search/at.go:17 --depth 1 internal/cli internal/search api` confirmed direct `SearchAt`, CLI `searchLocal`, local ask navigation and existing tests; the same query at `at.go:74` found local ask navigation and tests for `AtFromDocument`. Graph at `api/search_service.go:128` warned that its broader `api internal` source universe is **incomplete** (910 selected/parsed, 25 skipped, 4 recovered); do not claim exhaustive API/remote consumers. Text hits are not caller evidence; interface dispatch, reflective or out-of-repository users remain unproven.

## Acceptance and test matrix

| Family | Required selection | Negative/compatibility gates |
| --- | --- | --- |
| Registered code adapters (`go`, `java`, `kotlin`, `dart`, `swift`, `hcl`, `svelte`, `css`, `javascript`, `typescript`, `tsx`, `python`, `csharp`, `c`, `cpp`, `rust`, `php`, `shell`) | For each registered ID with an emitted typed role, round-trip an actual `@KIND:START-END` token to the same clean inclusive source lines; cover nearest versus outer scope, declaration/body and one-line spans where available. | Wrong kind/bounds, nested same-kind shorthand, malformed/error syntax, injected languages, comments, same-line constructs and unsupported node kinds fail rather than guess. |
| Markdown | Section heading and body token select proven section. | Fenced/list/quote fake headings and text before first heading yield no false section. |
| JSON | Exact delimiter-backed object/array, nested ancestor token and one-line container. | Same-line sibling ambiguity and malformed JSON fail closed. |
| YAML | Proven mapping/sequence/document from valid full stream. | Flow/multiline scalar, invalid later document, trailing comment/blank and uncertain parent bounds fail closed. |
| Plain text, unsupported paths, binary source | No parser scope selected. | Existing legacy `--at` retrieval remains unaffected. |
| CLI and API | Two-token form (quoted paths including `:`), shorthand, clean anchored/default/line-only/JSON, `At` and caller-owned `AtFromDocument`. | No source edit from a decorated row; old `--at`, graph, `--enclosing`, `--no-annotate-scopes`, and legacy remote requests unchanged. Unknown selector or failed resolution produces no partial stdout. |
| Remote and resource safety | Explicit error before any backend request for a remote selector; `--local` works when it truly suppresses remote. | No new wire fields unless a separate capability is designed; bounded parsing/line counts, overflow-safe integers, root confinement, no per-line reparse. |

Follow the live registry and `internal/parser/scope_annotations_registry_acceptance_test.go` when constructing table-driven coverage; do not assume every syntax shape is available in every grammar. Benchmarks and parse-count checks should show one bounded projection per selected file, not one parse per result line. Validation: focused parser/search/CLI/API/render tests, `make test`, focused race checks, formatting, skill-catalog consistency and `git diff --check`. The installed/user-profile skills are not updated by this contract.
