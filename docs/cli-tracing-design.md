# CLI tracing: proposed contract and trust boundary

Status: design for the opt-in implementation; this is **not** an enabled deployment. The existing public-parent rejection remains the default. References below name the current code; implementation and verification belong to subsequent plan steps.

## Existing topology and seams

- `internal/cli/args.go:20-60` loads a configuration snapshot and runs a command inside `outputspill.Run`; `internal/cli/application.go:80-137` dispatches it. `internal/cliruntime/context.go:39-86` has no invocation `context.Context` and constructs a new API client from `Environment.APIClient()`. Add an invocation context and explicit provider/client at the composition root, without changing embedded/test clients. Help and `setup` currently bypass this config path; their tracing is out of scope.
- `internal/apiclient/client.go:29-46,128-334` handles search, navigation, analysis, grit, raw/tree, repos and rules via `do`. `search_pages.go:43-57` goes through `json`/`do`. `auth.go:50-80,145-190` uses separate `authDo`; `client.go:336-402` refreshes with a new background context. Preserve bounded responses and redirect/auth behavior while instrumenting. Do not inject into device-provider OAuth traffic; auth bootstrap/logout may have privacy-safe CLIENT spans but no trusted-ingress propagation.
- Remote entrypoints that currently discard the calling context include `cli/search/remote.go:16-20,111-124` (plus pagination and navigation), `cli/get/get.go:80`, `cli/graph/{build,query}.go`, `cli/tree/tree.go:116`, `cli/{refs,repos,rules}`, `cli/ask/command.go:98` and `cli/auth/login.go:70,126`. Other CLI functions start background contexts for local work: scope this audit to actual backend calls. `--daemon` only supports architecture and graph (`cli/application.go:80-108`), with local daemon IPC: its local-only calls must not masquerade as backend HTTP spans; inspect fallback-to-direct separately.
- Backend `telemetry/adapter/runtime.go:88-127,153-164` uses an explicit private provider, parent-based sampling, bounded OTLP/HTTP exporter and no global propagator. `bridge.go:34-47,70-115` only verifies signed shard parents, ignores public router parents, strips baggage/tracestate and signs outgoing router-to-shard requests. `privacy.go:33-56` roots all unverified remote contexts. `httpserver/adapter/fiber.go:23-36` installs telemetry middleware before routes/auth. Router `/public` is guarded by `router/adapter/router_http.go:208-218,270-277`, but `auth/controller/routes.go:44-59` bypasses authentication in local/dev mode when `required` is false. Existing waterfall and real HTTP proof: `docs/tracing.md:10-47`, `tests/integration/telemetry/tracing_test.go:47-111`.

## User configuration and exporter

Example user-owned `~/.grepple/settings.json` (or `GREPPLE_SETTINGS`), independent of `.grepple/grepple.json` and `--no-repo-config`:

```json
{"telemetry":{"enabled":true,"trace_endpoint":"http://127.0.0.1:4318/v1/traces","trace_sample_ratio":1}}
```

Disabled if absent or `enabled:false`; enabled requires an exact `/v1/traces` URL, no userinfo, query, fragment, extra headers or env/resource attributes. Permit explicit loopback HTTP (including localhost and IPv6 loopback) and HTTPS only; reject other plain HTTP and NaN/infinite/out-of-range sample ratios (an omitted ratio defaults to 1 when enabled). Use a private `grepple-cli` OTel provider and explicit W3C TraceContext, not global SDK/propagators, no baggage, and no OTel auto-instrumentation that copies URLs. Root `cli.invocation` per command, fixed phase names for configuration, local execution, backend call and rendering; CLIENT span names from an endpoint-category allowlist, never dynamic URL/route/id. Attributes: fixed command category, sanitized method/status class, outcome and numeric duration/counts only. No arguments, search/source, repository/path, server URL/host, auth header, token, user/tenant, provider prompts, error text, span links/events or response body. Keep resource identity fixed to service.name only (`grepple-cli`). Match backend parent-based sampling: configured CLI root ratio in [0,1], default 1 when explicitly enabled for local diagnosis; absent/disabled provider makes no network calls. Bounded exporter queue and one short (e.g. <=2s) shutdown on every exit path after `outputspill.Run`; collector failure must never change command output/exit status. Record failures as a safe status category only.

Outbound propagation is limited to an explicitly selected same-origin Grepple backend request and only while tracing is enabled; never to the collector, OAuth provider or a redirect to a different origin. Preserve the existing `doRequest` authorized redirect guard and extend the no-cross-origin rule to headerless/unauthenticated requests; use a cloned per-invocation HTTP client/transport, not `http.DefaultClient` mutation. Disabled and non-backend calls must not carry headers. Concurrent invocation scopes must not mingle contexts. The local-trust policy below further limits when sending a parent is useful; a parent sent to a non-participating backend is ignored there, not proof of correlation.

## Proposed *restricted* router ingress (security gate)

**Do not accept trace context from general authenticated public traffic.** For a local diagnostic deployment only, add a separate router-only, disabled-by-default operator flag (for example `GREPPLE_TRUST_LOCAL_CLI_TRACES`). It must be effective only when telemetry is enabled, actual router authorization is required and succeeds (not the local/dev pass-through), the incoming connection's **direct socket peer** is loopback, and the route is an approved CLI `/public` route. Never trust `X-Forwarded-For`, forwarded host, a user-provided assertion or a client header alone. When any precondition fails, leave router/shard behavior unchanged: public traceparent/tracestate/baggage cannot influence a backend trace. Do not give the CLI `GREPPLE_TRACE_PROPAGATION_KEY`; the existing shard HMAC remains exclusive to router/shards.

A router HTTP server span is already started *before* route authorization. Therefore accepting a parent in the top-level Fiber middleware would violate the authorization condition. Instead, after successful `requireOrgAuth` **and** corpus gating, a dedicated trusted-CLI middleware parses only a strict W3C traceparent (valid 55-byte/version, nonzero IDs; reject duplicate headers), discards tracestate/baggage, and starts a sanitized nested `router.cli_request` SERVER span from that parent. Retain the **request-owned private tracer provider** before replacing the active parent context; starting via an ambient/global tracer after reparenting would silently lose the trace. Scope the resulting context to the subsequent `/public` handler and end it after the handler; do not reparent the pre-auth outer HTTP span. Add this operation to the backend privacy allowlist. Existing router operations/fan-out then inherit the nested span; signed propagation into shards remains unchanged. The independent outer router HTTP span/log represents pre-auth traffic and **will not be in the CLI trace**; test and document this intentional discontinuity rather than claiming every backend span joins. Fail closed for malformed/untrusted/unauthenticated/off-loopback input: no nested parent span and no downstream propagation of the supplied parent. A valid unsampled trusted parent may produce non-recording spans per parent-based sampling, not visible SigNoz entries; forged but syntactically valid input cannot be distinguished from legitimate input once a *trusted authenticated local peer* is granted trace-parent control, which is why this capability is restricted to that peer and disabled by default.

Direct loopback and real authentication are both required; Docker port-forwarded traffic usually appears as a bridge gateway rather than a loopback peer inside the container, so this does **not** promise joined CLI traces for the current Docker Compose stack or remote hosted routers. No acceptance via configurable CIDR, reverse proxy headers or generic user tokens in this iteration. To support remote/container ingress later, require a separately designed authenticated channel (e.g. mTLS or a dedicated narrowly scoped server-issued proof, with independent secrets) and review it before broadening the boundary. If direct-peer verification, middleware ordering, auth-required detection or privacy containment cannot be made reliable, do not implement parent acceptance; export independent CLI traces and document that no single trace is available. A server-generated correlation mechanism can be considered separately, but is not a substitute for a parent-child trace and must not expose trace IDs on public responses by default.

## Acceptance evidence

Test with real loopback HTTP sockets (not only `fiber.App.Test`): opt-in + required successful auth + eligible `/public` yields CLI CLIENT -> nested router SERVER -> router operation -> shard CLIENT -> signed shard SERVER; verify IDs, parent IDs and sampling. Repeat with two shards. Test off by default, unauthenticated, dev auth bypass, malformed/duplicate/forged parents, forwarded-IP spoofing, non-loopback peer, other routes, baggage/tracestate injection and redirects. Check that all public-facing non-participating requests have server-assigned roots, no header leaks to redirects/OTLP, and no private payloads in exported span bytes. `grepple-backend/tests/integration/telemetry/tracing_test.go` already covers signed shard fan-out and public rejection and can be extended without weakening existing assertions. This step makes no source/runtime or deployment changes.

## CLI lifecycle implemented in step 0002

`internal/config/user.go` now loads strict optional `telemetry` settings with `enabled` default false and `trace_sample_ratio` default 1 when enabled. `internal/clitelemetry` holds a private per-invocation OTLP/HTTP provider with bounded queue and flush budget. `internal/cli/args.go` creates the `cli.invocation` root only **after** user/repository settings load. `cli.command` is its child around dispatch and rendering; `cli.output_spill` is a subsequent sibling around output finalization (copy or artifact persistence) after command completion, not an enclosing command span. Configuration loading itself cannot be inside the configured trace without pre-reading user settings, so there is no fabricated configuration span. Help/setup bypass settings and tracing. CLI `--daemon` covers only local architecture/graph IPC and uses one CLI invocation root; it does not create a server-side daemon/backend trace. The command `cliruntime.Context.Invocation()` carries the command span explicitly.

## CLI HTTP coverage implemented in step 0003

`internal/apiclient/tracing.go` starts fixed-category child CLIENT spans for selected `/public` operations only with a valid opted-in invocation context; it manually injects W3C `traceparent` (no global propagator, baggage or tracestate). Search and cursor pages, navigation, grit, analysis, raw, tree, repositories and rules share `do`; requests include no dynamic URL, hostname, error text, credentials, query or body attributes. Only allowlisted methods, outcome categories and status class are exported. Auth configuration/logout receive headerless spans; refresh and device-provider OAuth requests have no CLIENT span and no traceparent (refresh still uses its independently bounded background context). Client-supplied injected HTTP transports remain untouched. With tracing disabled, behavior and cross-origin redirects are unchanged; for traced public requests, even unauthenticated redirects cannot carry `traceparent` to another origin. Same-origin redirects retain the header; redirects to unrecognized same-origin routes can still complete under the existing HTTP client policy. The CLI forwards its invocation context through remote commands and paging while preserving their timeouts and cancellation. Local graph/architecture daemon IPC, AI-provider login, local setup/init/hook and exporter calls do not receive backend trace headers. Explicitly selected `--server` origins may receive a CLI parent for an eligible backend route, but this is **not** authorization for router ingress.

## Backend gate implemented in step 0004

`grepple-backend/docs/tracing.md` documents the router-only, operator-disabled-by-default `GREPPLE_TRUST_LOCAL_CLI_TRACES` gate. It requires telemetry with trace exporter, required and successful local authentication, a matching validated Public corpus scope, an eligible `/public` route without further admin gates, and a verified direct TCP loopback peer. The nested `router.cli_request` SERVER span starts **after** authorization under the CLI CLIENT span; the pre-auth outer HTTP span remains an independent root. Default public rejection and router-signed shard propagation remain in place; only the nested child and downstream operations/shards share the CLI trace. This has hermetic real-socket and multi-shard integration tests but **no live rollout or Docker-forwarded acceptance**. On remote or bridge-peered deployments, export independent CLI/backend traces. No shard HMAC key belongs in CLI settings.
