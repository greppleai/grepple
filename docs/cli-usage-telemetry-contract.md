# CLI usage and latency telemetry contract (incremental)

This is the implementation contract for incrementally extending CLI telemetry. **Implemented now:** bounded parsed-command attributes, request-owned counts of primary local search/outline and graph source reads, parser counts only on instrumented paths, bounded local scan and search segment parse timing, cold graph resolve build timing, and observed output-finalization bytes. **Still proposed:** truthful delivered-result counts. See [cli-boundary-tracing.md](cli-boundary-tracing.md) for existing phase boundaries. Keep the user-opt-in, invocation-private OTLP/HTTP runtime, parent-based sampling and bounded exporter. Help, setup, argument/config failure and some pre-dispatch operations do not have invocation traces. No deployed collector or backend trust change is required.

## Span shape and safety

Keep the existing `cli.invocation` root with `cli.command` and, after it, a sibling `cli.output_spill` covering only finalization. The finalization sibling is absent on the artifacts-clean bypass; a failure before command dispatch has neither child. Local phases are children of the command, except initial search discovery and bounded scan/parse under `cli.search.local`, and local graph rendering/cache lookup/read/build under `cli.navigation.execute`. HTTP CLIENT spans describe actual outgoing requests; they may repeat for pages, but must not be confused with local scans. Retain the **10 whole-command-phase-spans-per-invocation** cap, excluding root/command/finalizer and actual HTTP request spans. At most one of each stage name in a command; do not start spans in file, worker, result, language or pagination loops. `cli.search.scan` times the actual parallel/windowed candidate scan or an outline's streamed read/parse/output loop; `cli.search.parse` times only the whole basic search structural-segment pass. `cli.navigation.read` times the actual graph fallback source-read batch, including attempts that fail; it is absent on a daemon hit but still occurs on a warm stored-snapshot query. `cli.navigation.build` measures the cold graph resolve `NewUniverse` plus `BuildGraph` path, never graph query or a daemon hit. `cli.navigation.query` remains unreported: language-manifest, stored-snapshot, monolithic and daemon paths have no universally shared pure build/query seam. `cli.render` times the selected output operation, **not** always pure formatting (outline streams from its inner scan). Timing is SDK span start/end **wall time**; nested or concurrent spans overlap and must not be added as serial CPU time.

Attribute keys, span names, outcomes, formats and flag names are finite, tested allowlists. Record values only from parsed typed options and code-observed counters. No argv or raw flag **values**, globs, patterns, source/text/response content, file/artifact paths, repository/user identity, symbols, endpoint/host/URL, error messages, digest, continuation token, baggage, tracestate, per-file events or dynamic span status. Do not pass private data even if a local collector is trusted. Numeric counts are nonnegative integers, never estimated or derived from labels. Disabled and unsampled invocations do not perform observation-only work.

## Command and flag vocabulary

`cli.command.name` derives a finite category from the parsed dispatch tree in `internal/cli/application.go`; `search` includes implicit and explicit search, `version` wins when requested, and `graph.resolve|callers|callees` are the only normal graph subcommands. **Implemented:** on `cli.command`, `cli.command.source_mode=local|mixed|remote` for search and focused graph where derivable (tree only for explicit remote `--repo`), and `cli.command.output_format=text|json|compact` for search, focused graph and tree. Selected `cli.command.option.*` Booleans are allowlisted `no_spill`, `no_repo_config`, `no_config_ignore`, `production_only`, `daemon_requested`, `at`, `outline`, `files`, `files_with_matches`, `count_summary`, `related_requested`, `no_related_requested`, `line_only`, `fixed_strings`, `ignore_case`, `json_matches`, `cursor_requested` and `metadata_filter_requested`; absent keys mean not selected or not applicable. `count_summary` includes the `--count-by-repo` alias. `related_requested` is a parsed request, **not** automatic navigation selection applied later. A Boolean derived from typed options does not prove literal spelling: `-O` and `--outline` are identical, defaults/aliases may be indistinguishable. Unsupported or ambiguous modes are omitted, including local/legacy positional tree targets. If literal flag presence is needed instead of typed selection, add a validated typed presence channel; never scrape or export raw argv. Do not include paths, queries, repositories, selector labels or numeric limit/depth/threshold values. Exact key/value and count budgets are guarded by `internal/cli/phase_contract_test.go`.

## Accounting units and applicability

| Quantity (implemented unless marked proposed) | Definition and limits |
| --- | --- |
| `cli.files.candidates` | Number of paths produced by the actual initial source discovery, **before** scan/window; if externally supplied or metadata-filtered, label selected candidates separately and do not misrepresent this as a newly timed discovery. A listing is not a content scan. |
| `cli.files.selected` | Observed on a local listing as paths admitted after listing policy/glob/repository filtering **before** output paging, or on a metadata-filtered content/`--at` search as the metadata-selected candidate set **before** later repository/scan guards. Absent on unfiltered content scan and unfiltered `--at`: neither reports a selected-universe size. Not the count opened or delivered. |
| `cli.files.attempted` | Number of actual local content-read attempts from this operation, not candidates scheduled in a parallel batch or files output. Count an attempted `--at` read, outline read or graph source read only if their adapters expose the event. A repeated read is a second attempt; not a unique-path cardinality. |
| `cli.files.read` | Successful local content reads, including empty or binary files. `cli.files.read_failed` counts attempted reads returning an error; no reader error strings. Noncontent `--files` discovery has zero local reads if explicitly measured. |
| `cli.files.bytes_read` | Sum of raw bytes from successful local content reads actually observed. Not UTF-8-normalized string length, server payload size, output size or filesystem size of untouched candidates. If partial streaming reads are supported later, name and test the partial-byte semantics instead of guessing. |
| `cli.files.parse_attempted`, `cli.files.parsed`, `cli.files.parse_failed` | Actual supported-grammar parser invocations and their returned error outcomes, not file matches, source syntax recovery, text/JSON/YAML lightweight scans or `LanguageFor`. Count search segment parses only on the complete basic segment path; scope/range/related parses remain unmeasured. A warm stored graph snapshot with no parse has zero only on its instrumented query path. Never infer `parsed` from cached report/manifest summaries. |
| `cli.results.emitted` (**proposed**) | Count of results actually delivered for this command's output in its documented unit (matching files for content search, listed files for `--files`, selected file outlines where known, declaration matches for graph). A count-summary aggregates all matches by repo; it is **not** a paged matching-file count. Rendering errors/truncation may make exact delivered-result count unavailable; omit the field instead of claiming that all selected objects were delivered. The existing `cli.results.count` reports returned local files **before** rendering, not delivered objects. |
| `cli.output.logical_bytes` | Captured command-output file size observed at finalization after renderer-level truncation and before any descriptor; zero for empty output. Not an estimate of full untruncated search results; excludes stderr. Absent if capture preparation or stat fails. |
| `cli.output.stdout_bytes` | Bytes successfully written to stdout during finalization, including partial writes and descriptor bytes if spilled, zero if a write failed before committing anything. Does not include artifact bytes or pre-dispatch/bypass writes. |
| `cli.output.artifact_bytes` | Bytes **newly persisted** to an immutable artifact when a spill succeeds, zero when content-addressed deduplication reuses an existing artifact; absent for inline output. Not the descriptor or bytes re-read to hash/check the file. |
| `cli.output.mode` | `inline` for copied output (including `--no-spill`, empty output, and partial/failed stdout copies); `spilled` only after successful artifact persist/reuse, even if descriptor writing fails. Absent if no branch completes (e.g. failed stat or failed persist) and on the artifacts-clean bypass, which has no finalization span. |

An absent measurement means **not observed/not applicable/failed before the seam**; a recorded zero means the instrumented operation ran and measured no such work. `internal/workaccount` owns atomic request-private counters attached to a context only for recording phases; `internal/clitelemetry/work.go` exports their fixed numeric allowlist on `cli.search.local` or `cli.navigation.execute` after workers join. `cli.files.candidates` is measured only from initial search/listing discovery; metadata selection is not newly timed discovery. Primary content scans include read failures, repeated reads, and bytes from successful `os.ReadFile` calls; path-window searches may stop early, count summaries/match-sorted searches scan all candidates, `--files-with-matches` scans while `--files` only lists, and stdin isn't a local file. Search segment parse counts are complete only in the basic no-related/no-scope/no-range segment path. They are **omitted** for `--at`, stdin, related-navigation, and scope/range modes, which may parse without an instrumented call site. Outline parse counts cover actual grammar calls but not JSON/YAML lightweight scanners or unsupported languages. Graph query fallback records source reads *before* the max-files parser gate and records parser calls only on a fresh universe; a warm stored snapshot records zero parses on the instrumented query path while still rereading source files to fence identity. Graph resolve parses its own universe. A daemon hit may have zero local reads but no parser-applicability field; a stored snapshot is not a daemon hit. File counts do **not** include work performed in related-navigation rediscovery/analysis or metadata preselection reads: these paths need separate instrumentation before claiming whole-invocation totals. Remote-only search/graph do not report local work or infer server scans from returned pages. On errors or cancellation, report only counts already observed, never planned totals or per-file details.

## Timing seams and proof

Already present: `cli.search.local` surrounds `searchLocal` and local outline execution; `cli.sources.discover` surrounds only initial `sources.Candidates/Listing` inside `FilesContext`/`ListFilePathsContext`, `cli.sources.resolve` surrounds graph path resolution, `cli.navigation.execute` surrounds daemon lookup + fallback/read/analysis/render, and `cli.navigation.cache_lookup` times only an actual daemon request. Search scan times `candidateScan.scanAll/scanWindowed` after discovery and before optional related navigation; the segment parse batch occurs after navigation and only for matching returned files. Listing, stdin and `--at` have no scan/parse stage because those entrypoints do not use these shared seams. `render.Outlines` discovers candidates with its discovery observer and times one inclusive streaming scan phase for its read/parse/output loop; stopping at a truncated/error writer still stops further reads exactly as before. Its outer `cli.render` and inner scan **overlap**; neither is pure parser CPU, and no bytes or phase counts are attributed to the scan stage. On graph fallback, `cli.navigation.read` surrounds `ReadSourcesContext` once, returning sources with read errors for later completeness accounting. Graph resolve's build phase follows source reads and excludes source path resolution, daemon lookup, declaration filtering and rendering. Graph query's `BuildStoredGraphContext` may open a language manifest or monolithic snapshot, rebuild, republish, or retry a fallback; `ReadSourcesContext` runs even for a warm local snapshot, so a fabricated universal `build`/`query` split would mislead. Its aggregate navigation span remains authoritative. Finalization uses an opt-in `internal/outputspill.OutputReport` callback only while the invocation records: it measures the captured temporary file, actual writes through a finalization-only writer, and successful artifact rename; it does not observe stderr or output before command dispatch. The finalization span is a sibling following the command, not a parent of rendering. Canceled or failed phases carry only fixed outcomes, never errors or selectors. Disabled and unsampled runs do not attach source observers, output writer wrappers or child stage spans.

Verification uses isolated settings and in-memory OTLP capture with an exact span/key/value allowlist, parentage and cap assertions, disabled/sampled-out checks, adversarial private-input tests, error/cancellation and concurrency fixtures, byte-for-byte stdout/exit parity and a disabled-path microbenchmark. Consult [cli-telemetry.md](cli-telemetry.md) for operator configuration; tests must not depend on SigNoz or modify settings. The implementation may narrow this proposed vocabulary where a truthful low-overhead measurement cannot be made; document such omissions instead of fabricating data.
