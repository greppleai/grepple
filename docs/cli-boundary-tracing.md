# CLI boundary tracing contract

Current opt-in tracing: `cli.invocation` -> `cli.command` (search/graph/HTTP children), followed by a sibling `cli.output_spill` for output finalization (copy to stdout or artifact persistence), **not** the whole command (`internal/cli/args.go`, `internal/outputspill/spill.go`). Parsing/help/config failure and `setup` return before the root. A failure before command dispatch has no command or finalize span; artifacts clean bypasses finalization. The runtime is private, parent-sampled, bounded on export/shutdown, and never installs a global tracer. **Implemented:** a parsed-command attribute, aggregate local search/candidate discovery, local graph path resolution and whole navigation, and one command-selected output span. `cli.navigation.cache_lookup` measures only an actual opt-in daemon lookup; `hit|miss` is never inferred for stored snapshots. Language-partitioned manifest, monolithic/reference and fallback paths may open or build multiple snapshots, so there is deliberately no separate `cli.navigation.build` or `cli.navigation.query` claim. Source telemetry stays off when user settings do not enable it; this design does not change backend ingress/trust.

## Source-backed boundary map

| Operation | Current path and the safe timing seam |
| --- | --- |
| Command | The parsed pointer tree and dispatch live in `internal/cli/application.go:36-71,81-138`; implicit search is normalized before parsing (`internal/cli/args.go:104-115`). Derive a finite category from parsed pointers; `--version` takes priority over subcommands. Only `graph resolve`, `graph callers`, `graph callees` are registered (`internal/cli/graph/arguments.go:15-35`); `graph build` and diff helpers are not normal reachable subcommands. No span for pretrace help/setup/parse errors. |
| Candidate/glob discovery | CLI local search passes its invocation child context to `search.FilesContext` / `search.ListFilePathsContext`; their explicit optional observer (`internal/search/discovery_observer.go`) surrounds only the initial `sources.Candidates/Listing` operation. Actual glob and walk loops remain in `internal/sources/discovery.go`. The observer is absent for other consumers and when candidates are already supplied. Do not put spans in discovery loops or precollect and pass candidates: that changes `fromIndex`/related-universe semantics. |
| Search | One outer span around the one `searchLocal` execution (including `--at`, listing, stdin, content and optional related navigation). `FilesContext:203-233` scans/ranks, attaches navigation and parallel-parses; `search_engine.go:236-275` may discover extra repository context. `runCountByRepo` separately scans all local matches (`cli/search/execution.go:303-366`); include it once, not per result/remote page. No local phase on remote-only. The candidate discovery child measures initial candidate collection, **not** later related-navigation discovery. |
| Graph path selection | `internal/cli/graph/{query,resolve}.go` call `resolveCLIPaths` (`graph/trace.go`) from invocation context. One `cli.sources.resolve` includes policy, discovery, sorting and cache-path filtering, with final path count. `ResolveInputPaths` retains the former no-context behavior for legacy callers; CLI-only `resolveInputPathsContext` passes the context to `search.ListFilePathsContext`. This phase is not labeled pure `glob`. |
| Graph build/cache/query | Local `executeQueryWithDaemon` and `executeResolveWithDaemon` start `cli.navigation.execute` after path selection, covering actual daemon lookup, source reading, stored-graph build/query or resolve projection, report metadata and output. One `cli.navigation.cache_lookup` child exists only with `--daemon` and marks `hit|miss` from `daemon.QueryGraph/QueryResolve`. Default language-manifest warm/open versus fresh build is in `internal/analysis/graph_languages.go:14-97`; monolithic/reference selection and snapshot open/rebuild live in `graph_stored.go:23-76`. `analysis/universe.go` parses/builds using `navigation/engine.go`. No snapshot cache-state claim or separate build/query child: one aggregate analysis seam is not available across language-partition, monolithic and fallback paths without broad signature changes or duplicate spans. |
| Rendering | `cli/search/execution.go` calls `clitelemetry.RenderPhase` once around the whole selected `render.Search`/`render.Render` operation or `render.RepoCounts`. Its outline branch wraps `render.Outlines` once, but that API also discovers and parses files: its span measures the **whole outline output operation**, not pure string formatting, and does not create a misleading local-search span. Local graph compact and JSON encoders are wrapped once under `cli.navigation.execute`; remote graph output is wrapped once under `cli.command` after the HTTP request. Retained nonregistered graph build output also uses the same no-op-safe wrapper. The helper does not wrap the writer or count bytes, so streaming, truncation, warnings and errors remain unchanged. No span in a file/result loop. After the command returns, `cli.output_spill` measures final output copy/persistence; it no longer encloses the command. |

Focused graph evidence: callers of `search.FilesContext` at depth 2 include CLI `searchLocal`, count-summary, ask/init and tests; callers of `sources.Candidates/Listing` include the search adapters. Callees of `cli/graph/query.go:57` include `ResolveInputPaths`, daemon lookup, source read, `BuildStoredGraph` and compact renderer. Callees of `analysis/graph_stored.go:23` include both language and monolithic paths; callers of `render.Search` include CLI search (other displayed graph candidate edges require source verification). Engine-wide instrumentation would also affect non-CLI consumers, so prefer orchestration seams.

## Fixed names, parents and safe attributes

**Hard budget:** at most **10 newly added phase spans per CLI invocation** beyond the existing invocation/spill/command/HTTP spans. At most one of each new name in the selected command execution. Count is independent of glob/file/result/depth/worker/page count; even errors and retries do not fan out. A narrower boundary is optional, not an excuse for noisy or incorrectly labeled spans.

| Name | Start/end and parent | Fixed-key attributes |
| --- | --- | --- |
| Existing `cli.command` | Existing output-spill callback, no new span | `cli.command.name` from a compiled finite parsed-pointer allowlist: `search` (implicit/explicit), `graph.resolve`, `graph.callers`, `graph.callees`, `version`, other registered command categories or `other`. No raw argv/subcommand. |
| `cli.search.local` | Before/after one local search or local count-summary scan; child of `cli.command` | `cli.search.mode=content|files|at|stdin|count_summary`, outcome, optional numeric result count already computed. |
| `cli.sources.discover` | Before/after one initial local-search candidate-collection call; child of local-search span; absent for supplied candidates/remote-only and for graph path selection (covered by `cli.sources.resolve`) | `cli.sources.mode=content|listing`, outcome, numeric candidate count on success. |
| `cli.sources.resolve` | Before/after one local graph path-resolution call; child of `cli.command` | Outcome, numeric final path count on success. |
| `cli.navigation.execute` | Before daemon lookup or source read/build, through completed report/output or error; child of `cli.command`, absent for remote-only graph | Outcome; no inferred snapshot cache state or unproven result counts. |
| `cli.navigation.cache_lookup` | Around one **opt-in** CLI daemon lookup only, child of navigation.execute | `cli.cache.kind=daemon`, `cli.cache.state=hit|miss` from actual lookup. Never infer a snapshot hit from timing. |
| No `cli.navigation.build` / `cli.navigation.query` | Deliberately absent: manifest, monolithic, reference, and fallback paths do not expose one reliable whole-build/whole-query split. | Do not infer snapshot hit/miss or count nested builds. |
| `cli.render` | Once around whole selected output operation. Child of `cli.navigation.execute` for local graph, of `cli.command` for search and remote graph. Absent if earlier source, query or response validation fails. | Outcome; `cli.render.format=text|json|compact` from a fixed branch; no output bytes, text, paths or error messages. |

Some names are mutually exclusive across command paths; enforce the global cap in tests rather than relying on the table's estimated maximum. HTTP CLIENT spans per actual request retain their existing cardinality; do not add page spans. No span starts inside a loop, recursion, per-file/per-result/per-language path, worker callback or paging callback. Attributes and names must exclude raw arguments, globs, paths, filenames, symbols, repository/tenant/user IDs, query/source content, hosts, URLs, credentials, errors, response text and generated next commands. Avoid exception events and `RecordError(err)` because raw errors can contain secrets; set fixed `ok|error|cancelled` (or `empty` for legitimate no-results) outcome and a static status description only. An empty result requesting exit 1 is not automatically an error.

## Context, validation and limitations

`cliruntime.Context.Invocation()` carries the command parent (`internal/cliruntime/context.go`). `StartPhase` requires a private SDK-backed runtime handle installed by the invocation, an opt-in marker, and a recording parent. `WithInvocationTrace` alone does not establish provider ownership. No ambient/global provider is installed. For disabled or sampled-out commands the helper is a no-op and emits no spans or network work. Explicit child context flows through nested local discovery and search; HTTP uses the invocation context. Existing backend traceparent eligibility, no baggage and no tracestate remain unchanged.

Search's candidate observer runs once around the first `sources.Candidates/Listing` call. Later related-navigation discovery, file scans, parse workers and ranking are covered only by the outer local-search span, not individually timed. Graph `resolveCLIPaths` measures source policy and candidate selection; `cli.navigation.execute` includes local graph output, with its one nested `cli.render` child. `cli.navigation.cache_lookup` is emitted only for an actual opt-in daemon lookup. Graph build/diff helper functions are not registered CLI commands. Outline's rendering span includes its own discovery/parse. There are no spans for file/result/glob/declaration iterations, page callbacks, recursive graph branches, per-worker callbacks or background indexing. These are latency partitions, not CPU profiling.

Tests use isolated `GREPPLE_SETTINGS` and an in-memory OTLP capture, not live SigNoz. The shared test contract separates per-request HTTP CLIENT spans from a hard cap of 10 new phases per invocation; it checks one trace tree, exact phase/attribute allowlists, fixed enum values, no arbitrary events/links/statuses, cold/warm and daemon miss/hit, disabled/unsampled behavior, errors, output bytes and sensitive-input absence. Search and graph JSON output are byte-equal with tracing enabled/disabled. A microbenchmark of a disabled no-op phase versus a baseline no-op span on one developer machine measured about 11 versus 6 ns/op, both 0 allocations; this is illustrative, not an end-to-end CLI latency guarantee. Absence of raw input in a fixture export is not a proof of every future attribute's privacy. For actual ingestion, use a **read-only** SigNoz Traces filter `service.name=grepple-cli`, then inspect one `cli.invocation` by trace ID and its `cli.command.name`. UI availability alone does not prove ingestion. No host settings, collector/backend deployment, credentials or ingress trust need change.
