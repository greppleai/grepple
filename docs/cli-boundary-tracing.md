# CLI boundary tracing contract

Current opt-in tracing: `cli.invocation` -> `cli.command` (search/graph/HTTP children), followed by a sibling `cli.output_spill` for **only** actual finalization (copy to stdout or artifact persistence), not the whole command (`internal/cli/args.go`, `internal/outputspill/spill.go`). Parsing/help/config failure and `setup` return before the root; output preparation can fail before a command child exists, and artifacts-clean bypasses finalization. The runtime is private, parent-sampled, bounded on export/shutdown, and never installs a global tracer. Implemented: finite parsed-command and option-presence attributes; observed local file, parser and output counts; bounded discovery/scan/parse and graph-source-read/resolve-build wall timings. A daemon cache `hit|miss` comes only from an actual opt-in daemon lookup, never from stored snapshot reuse. Language-manifest/monolithic/fallback graph *query* paths deliberately have no fabricated distinct build/query phase. Opt-in settings and backend ingress/trust are unchanged.

## Source-backed boundary map

| Operation | Current path and the safe timing seam |
| --- | --- |
| Parsed command | `internal/cli/{args,application,command_trace}.go`: parsed pointer tree yields fixed `cli.command.name`, effective format/source mode and selected option Booleans, never raw flag values. Implicit search normalizes before dispatch; help/setup and parsing errors precede tracing. |
| Search discovery | `internal/cli/search/execution.go:beginLocalSearch` attaches a request-local observer **only on a recording invocation**; `internal/search/discovery_observer.go` surrounds the actual initial `sources.Candidates/Listing` call in `FilesContext`/`ListFilePathsContext`. Already supplied candidates do not invent discovery. Later related-navigation rediscovery and metadata preselection are not attributed to the initial stage. |
| Local search, scan and parsing | `cli.search.local` includes one `searchLocal` / count-summary / outline operation. `internal/search/search_engine.go:FilesContext` times exactly one batch scan after discovery and an optional structural-segment parse batch after navigation. Windowed/parallel workers do not create per-file spans. Listing, stdin and `--at` do not use these scan/parse seams; scope/range/related parser totals are omitted instead of being guessed. Count-bearing parent attaches actual source reads/bytes and supported parser calls only where observable. |
| Outline | `internal/render/outlines.go` separately observes candidate discovery, then one inclusive `cli.search.scan` for its streamed read/parse/write loop, under `cli.search.local`. Its outer `cli.render` includes that scan because human output may stop reading at truncation or failed write; the scan is **not** pure parser CPU. Parser calls are counted only when grammar parsing actually happens. |
| Graph paths and query | `internal/cli/graph/{query,resolve,trace}.go`: `cli.sources.resolve` covers path policy/discovery once; `cli.navigation.execute` contains optional actual daemon lookup, one `cli.navigation.read` for fallback `ReadSourcesContext` (including warm stored-snapshot queries), and local rendering. Cold **resolve** has `cli.navigation.build` for `NewUniverseContext` plus `BuildGraph` after reads. Query can load, rebuild, publish or reuse language-manifest, monolithic or stored snapshots in `internal/analysis/graph_{languages,stored}.go`, so no universal distinct query/build span is emitted. A daemon hit emits neither fallback source reads nor resolve build. |
| Rendering and final output | `cli.render` wraps selected search/graph output only, nested in navigation for local graph or search-local for outline. `cli.output_spill` starts after `cli.command` ends; `internal/outputspill/spill.go` observes captured logical bytes and committed final stdout writes, plus **new** artifact bytes on successful rename (zero on deduplication). Large output's stdout is a descriptor, not the artifact. Disabled/unsampled runs do not wrap the final writer. |

These are source-backed seams, not a claim of total invocation CPU, complete related-navigation work, remotely performed reads or delivered result objects. `cli.results.count` is pre-render selection; `cli.results.emitted` is not available. Cross-check exact units in [cli-usage-telemetry-contract.md](cli-usage-telemetry-contract.md).

## Fixed names, parents and safe attributes

**Hard budget:** at most **10 newly added phase spans per CLI invocation** beyond the existing invocation/spill/command/HTTP spans. At most one of each new name in the selected command execution. Count is independent of glob/file/result/depth/worker/page count; even errors and retries do not fan out. A narrower boundary is optional, not an excuse for noisy or incorrectly labeled spans.

| Name | Start/end and parent | Fixed-key attributes |
| --- | --- | --- |
| `cli.command` | Child of invocation; ends before finalization | Allowlisted parsed category/modes and selected option Booleans, no argument values. |
| `cli.search.local` | One local search, count-summary or outline execution; child of command | Fixed mode/outcome, pre-render result count where applicable, observed local file/parse totals. |
| `cli.sources.discover` | One initial candidate collection under local search; absent for preselected paths | Fixed content/listing mode, outcome, observed path count. |
| `cli.search.scan` / `cli.search.parse` | One actual content scan and applicable structural parse batch under local search; outline scan also inside render | Fixed outcome only; no per-file/worker spans. |
| `cli.sources.resolve` | One graph path-resolution pass; child of command | Outcome, final path count where observed. |
| `cli.navigation.execute` | One graph fallback/daemon operation; child of command | Outcome, observed local file/parse counts where applicable. |
| `cli.navigation.cache_lookup` | One **actual** daemon lookup under navigation | Fixed `daemon` kind and observed `hit|miss`. |
| `cli.navigation.read` / `cli.navigation.build` | Fallback graph source-read batch and cold **resolve-only** build; children of navigation | Fixed outcome. No graph-query `cli.navigation.query` stage is emitted. |
| `cli.render` | Whole selected output operation under command, local-search (outline), or local navigation | Fixed format/outcome; not guaranteed pure formatter time. |
| `cli.output_spill` | Sibling after command under invocation, absent for bypass or preparation failure | `cli.output.mode=inline|spilled` where known; logical captured bytes, committed stdout bytes, newly persisted artifact bytes (spilled only). |

Some names are mutually exclusive across command paths; enforce the global cap in tests rather than relying on the table's estimated maximum. HTTP CLIENT spans per actual request retain their existing cardinality; do not add page spans. No span starts inside a loop, recursion, per-file/per-result/per-language path, worker callback or paging callback. Attributes and names must exclude raw arguments, globs, paths, filenames, symbols, repository/tenant/user IDs, query/source content, hosts, URLs, credentials, errors, response text and generated next commands. Avoid exception events and `RecordError(err)` because raw errors can contain secrets; phase outcomes are fixed `ok|error|cancelled` with static status descriptions only. An empty result requesting exit 1 is not automatically an error.

## Context, validation and limitations

`cliruntime.Context.Invocation()` carries the command parent (`internal/cliruntime/context.go`). `StartPhase` requires a private SDK-backed runtime handle installed by the invocation, an opt-in marker, and a recording parent. `WithInvocationTrace` alone does not establish provider ownership. No ambient/global provider is installed. For disabled or sampled-out commands the helper is a no-op and emits no spans or network work. Explicit child context flows through nested local discovery and search; HTTP uses the invocation context. Existing backend traceparent eligibility, no baggage and no tracestate remain unchanged.

The initial candidate observer does not cover metadata preselection or later related-navigation discovery. File count attributes count only instrumented local reads; parser counts omit unsupported/scope/range/related/`--at` paths where completeness is not established. Graph warm stored snapshots still read local sources while possibly parsing zero files. Output finalization measures bytes after renderer truncation, not full theoretical results; missing means not measured, recorded zero means measured none. Nested/parallel **wall times overlap** and cannot be summed as serial CPU. There are no per-file/result/glob/declaration/pagination/language/worker spans. The bounded whole-command budget remains 10 phases, separate from actual HTTP CLIENT requests.

Tests use isolated `GREPPLE_SETTINGS` and offline OTLP capture, not live SigNoz. The shared contract checks exact span/attribute/value allowlists, parentage, nonnegative numeric counts and the 10-phase cap; search, graph, output, daemon and disabled/sampled-out/error fixtures check observed units and private-input absence. A high-file-count test verifies fixed phase cardinality and output/exit parity; `BenchmarkDisabledPhase` isolates the no-op phase cost, and `BenchmarkCLIVersionTelemetryDisabled` includes command/config/output overhead. These are illustrative local microbenchmarks, **not** an end-to-end production performance guarantee or proof that every future field is private. For actual ingestion, use a **read-only** SigNoz Traces filter `service.name=grepple-cli`, then inspect a `cli.invocation` trace ID and `cli.command.name`. No host settings, collector/backend deployment, credentials or ingress trust need change.
